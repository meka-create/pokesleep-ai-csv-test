# 読取・確認・互換性ルール（試作）

## 対象項目
ニックネーム / 種族 / レベル / メインスキルレベル / 食材3枠 / メインスキル / 性格 / サブスキル5枠 / 一緒に眠った時間 / 色違い。
補助根拠としてSP、おてつだい時間、最大所持数を参照してよいがCSVに列を追加しない。

## 確認の基準
- 読めなかった文字、S/M、食材アイコンの一部、種族の複数候補、マスターとの矛盾はすべて要確認。
- テキストとして読み取れた候補が、マスターの唯一の候補だったとしても、読取自体が不明なら自動確定不可。
- 複数のAIが一致してもそれだけで正解とみなさない。
- 一緒に眠った時間・色違いは確認質問をしない。画像上で明確に確認できれば実値を使用し、不明ならCSV用の仮の値をそれぞれ0とする（`user-policy-default`）。本来の値を観察したと扱わない。
- 切り抜きは画像の文字やアイコンを改変せず、必要な周辺も残す。
- 一度の質問でできるだけ複数の不確定箇所をまとめる。
- 過去の172枚の正解表は**開発検証のみ**。実運用では持ち込まない。

## 互換性と新要素
- マスターの出典と検証状態は`KIT_VERSION.json`に従う。
- 未知の種族・食材・スキルを既存の値に置き換えることは禁止。
- 新要素がポケスリゲームには存在しても、pokesleep-toolで未対応なら互換CSVへ含めない。
- 除外には、対象画像と理由をユーザーへ説明した後、**その行をCSVから除外してよい**という明示承認が必要。
- 全件除外なら空CSVを作成しない。

## 表記
- ミュウ：画面のオールマイティーの括弧内具体スキルを同梱のCSV_SCHEMA.jsonの表記へ変換。
- エンテイ/ライコウ/スイクン：画面のタイプ注記をCSVの基礎スキル表記へ変換。
- 食材の「―」表示と未読を混同しない。未設定の空欄は**ミュウの食材3、ダークライの食材2・3**だけに限定し、各枠が明らかに未設定と観察できる場合かユーザーが確認した場合のみ。食材1の空欄は禁止。
- サブスキルの空欄は、幻ポケモンで画像上の未設定が確実な場合かユーザーが確認した場合に、`emptySubskillsConfirmed`で個別に記録。未読・見切れを空欄確定しない。
- 除外に対するユーザー本人の明示回答はチャット内で実際に取得し、その原文を内部記録する。除外する画像IDを明示した `除外承認: IMG-0001`、またはカンマ区切りの複数IDによる返答だけを受理する。AI作成の同意フラグは承認の証明とみなさない。
- ニックネームのカンマ・ダブルクォートはCSVで正しく引用処理。**改行（CR/LF）はpokesleep-tool実サイトで文字列破損が再現したため禁止。無断修正せずユーザーに確認。**

## v0.11 入力・互換性の共通安全基準
全ポケモンの各食材位置に、現在のマスターでそのスロットの数量が正の候補を要求。種族固有のメインスキル、サブスキル名・重複、性格、レベル、空欄位置も検証する。pokesleep-toolのCSV取込拒否は生成側のFAIL、受理後の値変更もFAILとし、ユーザーに無断で値を補正しない。

## v0.12 ストリンダーのフォルム・性格の互換性

ストリンダー (ハイ) / (ロー) の性格との不整合は実インポート往復で値が書き換わるため、勝手に補正せず画像を再確認し、疑義が残ればユーザーへ質問。ユーザーの明示確認なく性格やフォルムを変更しない。検証器は対応していない組合せを拒否する。


## v0.4 独立種族監査（進捗標準ONのまま）
- `SPECIES_AUDIT_GUIDE.md` 参照。補助数値は任意で記録する。画像から不明な値はnull、CSV既定0とは分離。
- 種族候補1件・数値1件一致は元画像の種族を見た証明にはならない。元画像の独立確認に従う。
- 数値が一致しないことだけを理由に種族候補を落とさない。CSV列追加・本番HOLD変更はしない。

## Blind30開発試験 v0.7 のユーザー確認UI
- 不明な個体は、必ず元ファイル名と実際の画像・そのままの切り抜きをユーザーに見せてから尋ねる。PLACEHOLDER画像は禁止。確認が必要な画像はHOLD。
- CSVはこの開発試験の試作 `*_DEVELOPMENT_ONLY_10.csv` として全件確認後に保存してリンク提示。本番CSVの許可フラグは変更しない。
- 進捗は約1分を目安に自然な区切りで試みる。進捗のために解析を中断・分割・待機しない。


## 画像確認時のインライン表示（v0.8a運用改善・必須）
- **画像は必ず現在のZIPの元画像バイトから取り出す。** 確認に必要な部分をPillow等の `crop` で画素非改変に切り出してもよい。補間・画像生成・ウェブ画像検索・別画像への置き換えは禁止。
- **質問と同じチャット返信の本文内で、対象画像をその場に描画する。** ChatGPTのユーザー可視Pythonであれば `from IPython.display import display, Image; display(Image(filename=実ファイルの絶対パス))`、その他の環境では実ファイルパスを検証してから埋め込み画像としてレンダリングする。モデル側だけの画像閲覧・リンクのみ・ダウンロードリンクのみを「ユーザーへ表示済み」と扱わない。
- 表示には元画像・切り抜きの**実データ**を使う。`PLACEHOLDER`、画像検索結果、外部の無関係な写真、作り物の画像は使わない。URLは必要でも補助とし、ユーザーにダウンロードさせることを必須にしない。
- インライン画像表示が実行環境の制限でできなければ、**「チャット内表示不可・確認保留」**と明記し、見えていない画像について返信を強要しない。ファイルリンクは任意の補助資料に留める。
- 質問本文では `IMG-0009 / 元ファイル名 / 確認したい文字 / 選択肢` を画像の近くに書く。画像が描画されたのを確認してから質問する。

## ニックネームの画面上の折り返しと内部改行の区別
- ポケスリ画面でニックネームが**表示枠の都合で2行になっただけ**なら、それだけで内部文字列にCR/LFがあると推定しない。読み取り可能な文字列は表示順に連結して扱う。例：1行目「オラクル」、2行目「★」→画像読取候補 **「オラクル★」**（内部改行の証拠ではない）。
- 明確な表示上の折り返しだけなら、改行削除の承認をユーザーに求めない。読み取れない文字、実際に改行があるという**別の独立証拠**、複数の合理的な読取候補がある場合だけ、画像をチャット内に直接描画して質問する。
- CSVのニックネームへの実際のCR/LF混入禁止・入力データの無断加工禁止・その他の未確認項目のHOLDは維持する。
